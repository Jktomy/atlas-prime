# Aegis Break Primary Prime Route Contract

## Controlling decision

While GitHub is the canonical Prime repository, **Aegis Break is Athena's
primary method for durable Prime changes**.

```text
Jayson instruction
-> exact Mission and restart-safe Preview
-> Aegis Break authority and route selection
-> one prepublication-complete candidate
-> one route-neutral Candidate Seal for initial publication
-> exact GitHub-native atomic tree and initial base-parent single-parent commit
-> one deterministic branch and one draft pull request
-> replacement-sealed non-force single-parent fast-forward repair commits only for candidate-caused defects
-> independent readback, validation, review, and Strikeforce on the final exact head
-> unchanged merge-ready pull request
-> Jayson-controlled permanence
```

Aegis Break is a bounded safety, route-selection, and construction method. It is
not a standing writer, repository engine, credential, settings authority, READY
authority, or permanence authority. The authenticated GitHub Git-data substrate
performs the bounded write and may act only on the exact sealed candidate.

## Current route identities

- `ATHENA_AEGIS_BREAK` — primary current-GitHub Athena method.
- `DIRECT_GITHUB_NATIVE_AEGIS_BREAK` — primary current-GitHub atomic write
  substrate; one initial sealed tree and base-parent single-parent commit, one
  branch, one draft PR, and replacement-sealed single-parent fast-forward repair
  commits only when candidate-caused defects are discovered.
- `ATHENA_PHOENIX_BLADE` — Athena executes one exact Sword; explicit route only.
- `JAYSON_OATHBRINGER` — independent recovery publisher and human-operated Sword
  route.
- `JAYSON_ARTEMIS_ARROW_BOW` — explicit delegated delivery to Thread Engine.
- `ATHENA_SPEAR` — preserved platform-neutral method and historical proof;
  GitHub Direct Spear dispatch is retired and future Gitea use remains separately
  gated through Mission #353 and PA-C06.

No route name aliases another. Repository substrate, authorizer, operator,
launcher, engine, credential principal, work surface, and permanence authority
remain independently bound.

## Exact candidate and mutation boundary

The current route requires:

1. current main, Mission, attempt, Preview, related transactions, branches, and
   pull requests read back before construction;
2. a closed exact path set and complete candidate bytes;
3. public-clean screening and protected-boundary enforcement;
4. applicable prepublication validation;
5. one deterministic Candidate Seal binding base, branch intent, paths, bytes,
   Git blob identities, candidate-content digest, expected tree, validation
   evidence, stop boundary, and rollback;
6. no-ref Git object staging only when necessary to determine the exact tree;
7. no commit, branch ref, or pull request before the seal is independently
   verified;
8. one initial single-parent publication commit whose parent is the exact canonical base;
9. one non-force branch update and one draft pull request;
10. after a candidate-caused defect, explicit invalidation of the prior seal and
    all dependent head-bound evidence, followed only by a newly verified
    replacement seal and one single-parent fast-forward repair commit on the same
    branch and PR;
11. exact remote branch, commit, parent, tree, path, blob, deletion, and PR
    readback before validation claims.

The final exact head, rather than the initial publication commit, is the
candidate subject to validation, review, Strikeforce, READY, and permanence.
Every repair commit must be single-parent, non-force, replacement-sealed, and
fast-forward from the previously verified head.

Piecemeal contents-API assembly, one-commit-per-file construction, direct main,
force push, history rewrite, duplicate branch or PR creation, blind retry,
cleanup after ambiguity, automatic READY, automatic merge, and standing
authority are forbidden.

## Current GitHub Spear retirement

`.github/workflows/athena-spear-issue-ingress.yml` is absent from the active tree.
New GitHub Issue comments cannot dispatch Direct Spear key, Preview, Execute, or
Resume jobs. The client, crypto, ingress implementation, schemas, fixtures, and
accepted proof remain dormant compatibility and future-design evidence. Source
presence never proves dispatch availability.

Historical AJ-01, CAP-015, PR #102, PR #349, PR #352, Spear/Arrow/Bow parity,
and Thread Engine proof remain truthful for their accepted journeys. They are
not rewritten into current-GitHub default-route claims.

## Mission Control and recovery

Mission Control names Aegis Break as the selected current-GitHub route at the
start of ordinary Prime work. It does not manufacture a failed Spear attempt or
fallback preamble. An explicitly selected unavailable route may still produce a
truthful terminal route receipt and proceed only through already authorized
fallbacks.

Recovery preserves one Mission, attempt, candidate, branch, and pull request.
Aegis Break resumes only after read-only reconciliation. Sword/Oathbringer
remains the independent recovery publisher. A connector or checkout failure does
not authorize duplicate work, weaker bytes, or an unsupported contents-API
assembly.

## Future Gitea boundary

Spear may become Gitea-native only after a separate PA-C06 Preview, version-pinned
adapter and runner design, approved crossing, secret-release replacement,
least-privilege token proof, replay and partial-state proof, branch/PR/check
parity, backup, restore, rollback, mirror, mobile/Athena access, and explicit
Jayson cutover. This contract activates none of those things and does not make
Gitea canonical.

## Stop and rollback

Stop before mutation on stale main, source or Preview drift, duplicate work,
unknown path applicability, protected content, incomplete candidate bytes,
unverifiable tree or seal, ambiguous Git object/ref/PR state, unsupported
validation, scope expansion, or unproven rollback.

Before merge, rollback is closing the exact draft PR while preserving evidence.
After merge, rollback is one reviewed revert or repair-forward PR. Never
force-push, rewrite history, erase accepted Spear evidence, or reactivate a
retired ingress through repository settings.
