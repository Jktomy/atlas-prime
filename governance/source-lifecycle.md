# Prime Source Lifecycle

Prime is the sole active canonical authored source. A source file controls only
the scope declared by its metadata and routing. Tests, generated indexes,
receipts, Previews, Issue text, chat, runtime state, and predecessor repositories
are evidence or projections, not competing authority.

`governance/repository-process-contract.md` governs the common complete-candidate,
validation, review, repair, permanence, and readback mechanics.
`governance/aegis-break-primary-route-contract.md` governs current-GitHub route
precedence.

## Lifecycle

1. **Capture** clean, durable meaning without protected values.
2. **Classify** it as identity, governance, Project, Operation, Quest, protocol,
   runbook, template, infrastructure source, generator, or evidence.
3. **Route** every canonical file from an active command or registry surface.
4. **Lock** the exact canonical repository, main head, controlling source, and
   transaction identity.
5. **Discover** the complete deterministically knowable source, continuity,
   recovery, schema, test, and generated consequences.
6. **Author** one prepublication-complete candidate with exact paths, bytes,
   hashes, tree, stop point, and rollback.
7. **Seal** the route-neutral candidate before commit, branch, or pull-request
   mutation.
8. **Deliver on current GitHub** through Aegis Break over one exact atomic
   Git-data tree, single-parent commit, deterministic branch, and draft PR.
9. **Validate and review** through the mandatory baseline, affected invariants,
   required platforms, actionable review reconciliation, and at most one normal
   consolidated repair.
10. **Strikeforce** the unchanged exact candidate head through Noctua, Ares, and
    Aegis.
11. **Ready** only the unchanged validated head. Without Shardblade authority,
    report `Prime PR #___ is ready to merge.`
12. **Merge** manually by Jayson by default, or through one exact
    transaction-scoped Shardblade action when explicitly authorized.
13. **Read back** the merged PR, merge SHA, canonical main, tree, paths,
    continuity, generated-state consequence, receipts, and rollback posture.
14. **Diagnose** nonauthoritative projections in temporary storage.
15. **Sunset** superseded source with an explicit replacement or archive pointer.

## Source boundaries

- Active source must be necessary, current, nonduplicative, and Prime-native.
- Historical, failed, Preview, Harvest, closeout, release, and predecessor-only
  material remains evidence unless a current contract explicitly requires a
  sanitized record.
- Private evidence stays in its approved evidence system; Prime may keep only
  sanitized policy and pointers.
- A source removal requires a disposition: KEEP, MERGE, REMODEL, REGENERATE,
  ARCHIVE, or EXCLUDE.
- Projection diagnostics are temporary, carry their source fingerprint, and are
  reproducible from merged Prime source.
- A partial candidate is not made acceptable by calling the PR a draft.

## Change routes

- Current GitHub ordinary source: Athena -> Aegis Break -> exact atomic
  GitHub-native candidate transaction.
- Explicit delegated carrier: Jayson/Artemis -> Arrow/Bow -> Thread Engine.
- Explicit Athena Sword: Phoenix Blade.
- Independent recovery: Sword/Oathbringer after read-only reconciliation.
- GitHub Direct Spear Issue ingress: retired from new dispatch.
- Future Gitea Spear: planning only until PA-C06 proof and cutover.
- Projection diagnostics: read-only temporary evaluation; no follow-up
  publication transaction.

## Permanence authority

A direct Jayson instruction to change, repair, update, add to, or Sunset Prime
authorizes one bounded transaction through merge-ready, unless explicitly
narrower. `with Goddess Mode` authorizes bounded completion only inside that
transaction and never grants permanence. Machine merge requires current explicit
Shardblade authority plus exact-head status, review, Strikeforce, replay,
rollback, and compare-and-swap readback.

If candidate bytes change after READY, return the PR to draft, revalidate and
review the replacement exact head, repeat Strikeforce, and use exact current
permanence authority. Post-merge correction uses a reviewed repair-forward or
revert PR; history rewrite is forbidden.

`Jktomy/atlas-codex` is predecessor and rollback evidence only. It is never an
active source, runtime dependency, recovery dependency, or update destination.
